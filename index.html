How BillGuard AI Works

Detection methodology, limitations, and IBM Granite integration

🔍 What Does BillGuard AI Detect?

📈
Consumption Spike

Units significantly above the dataset average (Z-score > 1.8σ).

📉
Consumption Drop

Units significantly below average — possible meter bypass or tampering.

💸
Billing Inconsistency

Billed amount deviates >20% from tariff × units consumed.

🔢
Meter Reading Error

Reading gap doesn't match reported consumption (gap >5 units).

👤
Personal Drop / Spike

Consumer's usage drops >60% or rises >250% vs their own previous month.

⚙️
Faulty Meter Status

Meter flagged as Faulty, Tampered, or any non-Active status.

📊 Detection Method

BillGuard AI combines Z-score statistics (dataset-level) with rule-based checks (per-consumer history). Each record is analysed independently. Flagged records are assigned a severity level (High / Medium / Low) based on the type and magnitude of deviation.

Disclaimer: This tool surfaces patterns that require verification. It does not confirm or allege any fraud. All flagged records should be reviewed by a qualified human inspector before action is taken.

🤖 IBM Granite AI Integration

When IBM Cloud credentials are configured in the backend, BillGuard AI sends a summary of detection results to IBM Granite (via watsonx.ai) to generate plain-language explanations, pattern summaries, and verification recommendations.

Without credentials: The application runs fully using the local detection engine. AI explanation panels show clearly labelled Demo Mode responses generated locally.

To configure IBM Granite, see backend/.env.example and start the backend server with node backend/server.js.
